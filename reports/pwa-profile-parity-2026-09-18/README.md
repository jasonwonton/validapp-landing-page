# Profile settings and chat entry parity — September 18, 2026

Release web-v104, `b7a7f5198557d2fed11f`.

Chat search is hidden until the header Search button is tapped. Cancel/Escape clears the search, restores the conversation list and ignores late responses. Reopening a cached room now renders its latest window and sets the scroll position synchronously after showing the room, before the first paint. Refreshing an already-open room retains an intentional reading anchor; explicit message links still open their target. Current Memento access checks remain required before displaying gated messages.

Profile now follows the native SettingsView's Appearance card: System/Light/Dark buttons, matching symbol choices, 66px minimum height, selected peach treatment and black text in both themes, and explanatory text. Existing device persistence and haptics remain. Privacy & Safety contains Activity Status and Blocked Users. Blocked Users uses the existing authenticated profiles and DELETE block APIs, displays an empty state, confirms unblock, keeps failures retryable and removes rows only after success. Browser-specific passkey/notification/install controls remain above these cards. Leave Feedback and Sign out are separate full-width stacked buttons beneath Privacy & Safety.

Validation: 56 existing appearance/scrolling browser cases; 16 settings/search/unblock cases; four first-frame cached-room checks with a stalled refresh; four selected-theme contrast rechecks; 18 camera/profile affordance checks (two existing unsupported-camera skips). All passed across the configured Chromium, Firefox and WebKit projects. Runtime contracts, build, performance budget (732,076 estimated shell transfer bytes), 65 built asset hashes, old-release lazy modules, four-browser startup and offline/API-cache isolation passed. Final dark-mode settings layout was inspected in the built browser preview. No real users were blocked/unblocked and no feedback was sent during tests.
